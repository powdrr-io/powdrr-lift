# Agent/service split baseline

Baseline commit: `ff81b5cd` (`main` at the start of this PR).

This report records the runnable behavior against which later extraction PRs
must compare. It does not claim that the existing implementation already has
clean package boundaries. The first-pass ownership inventory is
[`agent-service-module-ownership.json`](agent-service-module-ownership.json).
Representative behavior fixtures and their asserted stable outcomes are listed
in [`agent-service-baseline-fixtures.json`](agent-service-baseline-fixtures.json).
CLI command names and descriptions are captured in
[`powdrr-lift-help.txt`](powdrr-lift-help.txt).

## Entry points and resources

- `powdrr-lift` resolves to `powdrr_lift.cli:main`.
- `powdrr-lift-mcp` resolves to `powdrr_lift.mcp_server:main`.
- The CLI currently exposes 81 registered command names/aliases covering
  planning, planning resume/repair, design, implementation, artifact state,
  validation/evaluation, GitHub workers, MCP-adjacent workflow tools, and
  benchmark harnesses. The captured help is the detailed CLI compatibility
  baseline; aliases and exit behavior must be preserved during migration.
- The package build includes three first-party import roots:
  `powdrr_lift`, `procedrr`, and `procedrr_evaluator`.
- Powdrr process definitions are loaded from `docs/procedrr/processes` and
  installed as package data. The ownership inventory enumerates each definition.
- The deterministic workflow scenario suite contains eight scenarios. Its
  stable baseline is all eight `passed`; the suite report is generated by CI
  rather than committed because it contains checkout-specific absolute paths.

## Representative behavior fixtures

The fixture matrix points to existing tests instead of inventing a second set
of mocked outputs. These tests assert source/answer identity, exact artifact
counts and IDs, dependency order, pass/fail gates, clean repository state,
commit behavior, and resume results. PRs that move a behavior must run the
referenced fixtures against the new entry point and compare those assertions.

The implementation end-to-end fixture intentionally uses a deterministic
worker adapter to keep the expected output reproducible. It proves local
worktree, MiniSWE-authoring interface, validation and artifact flow; it does not
claim live-provider coverage. The opt-in live tests remain separately marked.
Benchmark verifier contents remain test inputs only and must never be copied
into planner, implementation-prompt, or probe-author inputs.

## Verification on the baseline checkout

Verification on this baseline includes repository-wide Ruff format and lint,
mypy, Procedrr process validation, the full pytest suite with branch coverage,
and the deterministic workflow scenario suite. The results are:

- Pytest with branch coverage: 1,849 items; 1,843 passed and 6 skipped.
- Procedrr process validation: 36 process definitions validated.
- Deterministic scenarios: 8 of 8 passed.
- Ruff format and lint: passed across the repository.
- Mypy: passed across 386 source files.
- CLI help capture: `powdrr-lift --help` completed successfully.

No API/service split or runtime behavior change is part of this baseline PR.
